# 노하우: 외부 API·데이터 소스 (문서를 믿지 말고 실측한다)

> 출처: 프로젝트 실측(2026-08~). 스택 중립 — MCP 서버 도구 연동 적용.

---

## 1. 착수 전 실측

- **문서·기억 속의 필드명·모델명·엔드포인트를 믿지 않는다.** 원본을 열어 실제 이름과 데이터 형식을 확인한다.
- **커버리지도 실측한다.**
- **"실측으로 확인"이라 기록할 때 표본 수와 확인 파라미터를 함께 적는다.**

---

## 2. 응답 처리

- **200이 성공이 아닐 수 있다 — 상태 코드가 아니라 본문을 확인한다.** 일부 API는 에러를 HTTP 200에 `{"error": ...}` 페이로드로 반환한다.
- **정렬이 호출마다 다를 수 있다** — 일관된 LLM 응답을 위해 안정적인 키로 재정렬한다.
- **부분일치를 주는 API는 정확일치 필터 없이 쓰면 엉뚱한 것이 올라간다.**
- **확인한 형식만 파싱하고 원문(raw)은 항상 보존한다.**
- **HTTP 타임아웃은 필수다**:
  - `httpx` 등 비동기 HTTP 클라이언트 사용 시 반드시 전체 타임아웃(예: `timeout=10.0`)을 명시한다.
  - 타임아웃이 없으면 외부 API 지연 시 MCP stdio 이벤트 루프가 영구히 행(hang)에 빠진다.

---

## 3. 파일 및 로컬 데이터 소스

- **파서는 처음부터 1:N을 전제로 짠다.**
- **파일 앞부분 샘플만 보고 형식을 단정하지 않는다.**
- **번들하는 외부 데이터의 라이선스 고지는 모든 배포 형태에 필요하다.**

---

## 4. 네트워크와 핵심 기능의 분리

- **네트워크 기능이 추가돼도 서버 시작·핵심 도구 등록은 네트워크를 기다리지 않게 초기화를 분리한다.**
  - 서버 기동 시점에 원격 API 핑을 동기적으로 치지 말 것.
- **오류 원인 판정에 순서를 명시한다.**
- **무료 조회는 미리 해 캐시에 남기면 LLM 도구 응답 체감 시간을 0으로 만들 수 있다.**

---

## 5. 의존성 관리

- **메이저 버전이 막 올라간 의존성은 버전을 고정한다.**
- **의존성 설치는 Non-interactive 모드로 진행한다** (`pip install --no-input` 또는 `uv sync`).
