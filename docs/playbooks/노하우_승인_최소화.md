# 노하우: 명령 승인 최소화 (Antigravity 환경)

> **독자: AI 에이전트.**
> Antigravity 환경에서는 에이전트가 실행하는 **모든 `run_command` 호출에 대해 사용자의 수동 승인이 필요**하다.
> 승인 대기는 작업 흐름을 끊고 전체 프로젝트 속도를 늦추는 가장 큰 병목이다.
> 이를 최소화하기 위한 핵심 행동 강령이다.

## 1. 불필요한 명령 실행 금지

- **파일 읽기는 `view_file` 도구를 사용한다.** `cat`, `type`, `head` 등의 셸 명령을 사용하여 파일을 읽지 마라.
- **파일 쓰기/수정은 `write_to_file`, `replace_file_content` 도구를 사용한다.** `echo`, `sed` 등을 이용해 셸에서 파일을 편집하려 하지 마라.
- **디렉토리/파일 목록이나 검색은 파일 뷰 도구를 우선 활용한다.** 직접 셸 명령을 실행하지 마라.
- **단순 정보 확인을 위한 일회성 스크립트 실행을 자제한다.** 코드 내부의 로직을 파악하기 위해 파이썬 셸이나 REPL을 띄우는 것보다 정적 코드를 분석하는 것이 우선이다.

## 2. 명령 일괄 처리 (Batching)

- **관련된 작업은 셸 스크립트 하나로 모아 한 번의 승인으로 끝낸다.**
  여러 개의 `run_command`를 연달아 호출하면 매번 사용자의 승인을 기다려야 한다.
  예를 들어 가상환경 생성 및 의존성 설치, 마이그레이션 등 순차 실행 작업은 임시 스크립트(`.bat` 또는 `.ps1`)를 `write_to_file`로 만든 후, 한 번에 실행(`run_command`)하여 승인을 1회로 줄인다.

## 3. 사용자 입력 대기(Interactive) 툴 사용 금지

- **모든 셸 명령은 Non-interactive 모드로 실행되어야 한다.**
  프롬프트에서 사용자 입력을 기다리는 명령(`python -i`, 대화형 초기화 등)은 승인 후 실행되더라도 프로세스가 멈추어 데드락을 유발한다.
- 패키지 설치 시 `--no-input` 옵션을 반드시 붙이거나, CI/CD 환경처럼 동작하도록 플래그를 추가한다 (`pip install --no-input`, `uv sync` 등).

## 4. 백그라운드 작업 활용

- 시간이 오래 걸리는 작업(MCP Inspector 기동, 서버 지속 실행 테스트 등)은 `WaitMsBeforeAsync`를 적절히 주어 백그라운드로 넘기고, 다른 작업을 수행한다.
- `manage_task`와 `schedule` 도구를 활용하여 비동기 처리의 이점을 살린다. 단, 이 경우에도 최초 실행 승인은 1회 발생한다.

## 5. 검증 과정 최적화

- 테스트를 수행할 때 하나씩 여러 번 실행하기보다는, 전체 테스트 묶음이나 관련된 파일/모듈 단위로 한 번에 테스트를 실행한다.
- `python -m pytest tests/` 등 모아서 실행하여 승인 대기를 줄인다.
